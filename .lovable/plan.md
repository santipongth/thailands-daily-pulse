# แผนปรับหน้าวันนี้และความสดของแหล่งข้อมูล

## ผลที่ต้องการ
- หน้า “วันนี้” ย้าย “ตัวอย่างค่าใช้จ่ายครัวเรือนต่อวัน” ไปต่อจาก “ความเคลื่อนไหวจากหน่วยงานราชการ” และใช้หน้าตาแบบเดียวกับส่วนข่าวหน่วยงาน โดยคงตัวเลข สูตร และตารางเดิมให้อ่านง่ายทั้งมือถือและจอใหญ่
- Longdo Traffic Index ดึงข้อมูลรายชั่วโมงจริง และทะเบียนแหล่งข้อมูลแสดง “รายชั่วโมง” ตรงกับการทำงาน
- ทุกแหล่งในทะเบียนถือว่าข้อมูลเก่าเมื่อ **เกิน 1 วัน**; สถานะข้อมูลเก่า/ตรวจสอบไม่ได้และเหตุผลในหน้าแหล่งข้อมูลกับ Daily Brief ต้องตรงกัน
- FM91 Trafficpro (X) ลองส่งคำขอใหม่แบบหน่วงเวลาหลังพบความผิดพลาดชั่วคราว โดยไม่สร้างโพสต์ซ้ำและไม่แสดงว่าดึงสำเร็จทั้งที่ไม่มีข้อมูลที่ตรวจได้

## วิธีดำเนินการ
1. ปรับลำดับหน้า “วันนี้”: Social Media → ความเคลื่อนไหวจากหน่วยงานราชการ → ค่าใช้จ่ายครัวเรือน → สลากงวดล่าสุด. ให้ส่วนค่าใช้จ่ายใช้กรอบหัวข้อ เส้นแบ่ง ระยะห่าง และตัวอักษรแนวเดียวกับข่าวหน่วยงาน แทนพื้นผิวแผงข้อมูลแบบเดิม; คงตารางที่เลื่อนอ่านได้บนมือถือ. กรณีไม่มีข่าวหน่วยงาน ส่วนค่าใช้จ่ายยังแสดงตามปกติ.
2. ตั้ง Longdo เป็นงานรายชั่วโมงโดยเฉพาะ แยกจากเกณฑ์รวมที่ปัจจุบันอาจเว้นถึง 3 ชั่วโมง; คงการป้องกันงานซ้อนและไม่ดึงซ้ำเกินหนึ่งครั้งต่อรอบ. แก้ชื่อรอบอัปเดตในทะเบียนด้วย ไม่เปลี่ยนรอบของแหล่งอื่น.
3. เพิ่ม migration อัปเดต `source_registry.stale_after_days = 1` ทุกแถว รวมทั้งค่าเริ่มต้นสำหรับแหล่งใหม่; แก้แถว Longdo ให้ `cadence = 'รายชั่วโมง'`. ตรวจว่าการแสดงสถานะ/เหตุผลใช้เกณฑ์จากทะเบียนเดียวกัน และทำให้แหล่งที่ออกรายงวด เช่น สลาก แสดง “เก่า” ตามกฎใหม่โดยไม่ลบผลงวดล่าสุดหรืออ้างว่าไม่มีผลสลาก.
4. ในการดึง FM91 ผ่าน Firecrawl เพิ่ม retry จำกัดจำนวนครั้ง พร้อมหน่วงเวลาแบบเพิ่มขึ้นสำหรับ 429, 5xx และปัญหาเครือข่าย; เคารพ Retry-After ถ้ามี. หากได้ผลลัพธ์ว่างหรือรูปแบบโพสต์อ่านไม่ได้ ให้ลองใหม่แบบจำกัดครั้งและบันทึกเหตุผลจริงเมื่อยังล้มเหลว. ไม่ retry 401/403/402 หรือความผิดพลาดถาวร; คงการกันงานซ้อน, การคัดกรอง AI, การเก็บหลักฐาน และรอบ 30 นาทีเดิม. แยกสถานะ “ดึงได้แต่ไม่มีโพสต์ใหม่” ออกจาก “ดึงไม่ได้” อย่างตรงไปตรงมา.
5. ตรวจหน้า “วันนี้” ที่มือถือ/จอใหญ่, หน้าทะเบียนแหล่งข้อมูลและ Daily Brief, ประวัติงาน FM91 และการดึง Longdo รายชั่วโมง. ทดสอบ retry แบบจำลอง 500/429/ผลลัพธ์ว่าง/สำเร็จ รวมทั้งกรณีหมดรอบลองใหม่; ตรวจว่า Brief เก่าที่เผยแพร่แล้วไม่ถูกแก้ย้อนหลัง.

## รายละเอียดทางเทคนิค
- ปัจจุบัน `source_registry` มี 19 แหล่ง; หลายแถวตั้งเกณฑ์ 2, 3, 7 หรือ 17 วัน ขณะที่ Longdo แสดง “ทุก 5–15 นาที”. ระบบดึงข้อมูลรวมถูกครอนเรียกทุกชั่วโมงแต่มีเงื่อนไขข้ามเมื่อข้อมูลยังไม่เกิน 3 ชั่วโมง จึงต้องให้ Longdo มีการตัดสินใจรายชั่วโมงของตัวเอง.
- ประวัติ FM91 ล่าสุดที่ตรวจพบมีทั้ง Firecrawl 500 และ “ไม่พบโพสต์ในหน้า X” สลับกับรอบที่สำเร็จ; retry จะช่วยกับปัญหาชั่วคราว แต่ไม่รับประกันว่า Firecrawl/X จะพร้อมใช้งานทุกครั้ง.
- ไม่เปลี่ยนเกณฑ์ตรวจจับสัญญาณ สูตรผลกระทบ การจัดอันดับ หรือเวลาปิดรับ Daily Brief; ไม่เผยแพร่เว็บจริงในงานนี้.
