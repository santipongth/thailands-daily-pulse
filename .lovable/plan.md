# จัดรูปแบบ “สัญญาณวันนี้” ให้สม่ำเสมอ

## สิ่งที่ตรวจพบ
- การ์ดใน “สัญญาณวันนี้” ใช้โครงหลักเดียวกัน แต่มีกราฟรายสัปดาห์เฉพาะอาหาร (ราคาเฉลี่ย 7 วันล่าสุดเทียบ 7 วันก่อน) และรถไฟฟ้า (จำนวนประกาศวันนี้เทียบค่าเฉลี่ยย้อนหลัง 7 วัน) เท่านั้น; สัญญาณตัวเลขประเภทอื่นยังแสดงเพียงกราฟเส้นเล็ก ไม่มีการเทียบรายสัปดาห์
- กล่องสีเขียว “ข้อมูลจริง” อยู่ท้ายการ์ดสัญญาณ ส่วนประกาศตัวเลขรอบใหม่ถูกแสดงแยกเหนือหัวข้อ “สัญญาณวันนี้” อยู่แล้ว
- การ์ดสำคัญมากกินพื้นที่สองช่อง แต่การ์ดอื่นกินช่องเดียวในตารางสี่ช่อง ทำให้ชื่อยาวและกราฟแคบ อ่านยาก

## แผนปรับปรุง
1. ใช้โครงการ์ดแบบเดียวกันสำหรับ **ทุกประเภทที่ปรากฏใน “สัญญาณวันนี้”**: หมวด/ความสำคัญ, หัวข้อ, ค่าที่เปลี่ยนหรือจำนวนเหตุการณ์, ช่วงเวลาที่เทียบ, กราฟรายสัปดาห์, แหล่งข้อมูล และทางไปดูคำอธิบาย จัดลำดับสายตาและระยะห่างให้อ่านได้ทั้งโทรศัพท์และจอใหญ่ โดยความสำคัญยังแยกด้วยสี/ข้อความ ไม่ทำให้บางการ์ดแคบกว่าการ์ดอื่น
2. เพิ่มกราฟเปรียบเทียบ **7 วันล่าสุดกับ 7 วันก่อนหน้า** ในกรอบกราฟรูปแบบเดียวกันทุกการ์ด: ค่าตัวเลขใช้ค่าเฉลี่ยจากวันที่มีข้อมูลจริง, รถไฟฟ้าใช้จำนวนประกาศผิดปกติที่นับเป็นสัญญาณในแต่ละช่วง 7 วัน พร้อมคงข้อความประกาศเต็ม เวลา และลิงก์ต้นทางไว้ ข้อความบนกราฟระบุชนิดของค่าที่เปรียบเทียบให้ตรงกับข้อมูลจริง
3. สำหรับข้อมูลที่ออกไม่ถี่หรือย้อนหลังไม่ครบ ให้แสดงจำนวนวันที่มีข้อมูล/จำนวนประกาศ และสถานะ “ข้อมูลไม่พอสำหรับเทียบ” แทนการเติมค่าเองหรือแสดงศูนย์หลอก; แยกให้ชัดว่ากราฟรายสัปดาห์เป็นบริบทเพิ่มเติม ไม่ใช่เกณฑ์ตรวจจับสัญญาณของทุกหมวด
4. เอาเฉพาะกล่องสีเขียว “ข้อมูลจริง” ออกจากการ์ดในส่วนนี้; ป้าย “ข้อมูลตัวอย่าง” ยังอยู่หากมีข้อมูลตัวอย่าง เพื่อไม่ให้เข้าใจผิด และคงการระบุแหล่งข้อมูล
5. ตรวจทุกชนิดสัญญาณที่การ์ดรองรับ ได้แก่ ราคา/ตัวเลขทั่วไป, การข้ามระดับ, และเหตุการณ์รถไฟฟ้า ด้วยกรณีข้อมูลครบ/ขาด/ไม่มีข้อมูลย้อนหลัง; ตรวจหน้าจอเล็กและใหญ่ รวมถึงการ์ดข้อความยาวไม่ชนกัน และไม่เปลี่ยนเกณฑ์ตรวจจับหรือเพิ่มสัญญาณที่ไม่เกินเกณฑ์

## รายละเอียดทางเทคนิค
- ปรับการแสดงผลใน `src/routes/index.tsx` และ `src/components/signals-ui.tsx`; จัดกราฟของ `cost-signal-chart.tsx` และ `rail-signal-chart.tsx` ให้ใช้กรอบการเปรียบเทียบร่วมกัน พร้อมกราฟสำหรับสัญญาณตัวเลข/ระดับที่ยังไม่มี
- ใช้ observations และ social_posts ที่บันทึกแล้วเท่านั้น; วันอ้างอิงของอาหารใช้วันที่ราคาจริงใน checks, รถไฟฟ้าใช้ rail_day/rail_status ตามกฎนับปัจจุบัน และข้อมูลอื่นใช้วันที่สัญญาณ โดยไม่แก้ SQL เกณฑ์หรือข้อมูลหลังบ้าน
