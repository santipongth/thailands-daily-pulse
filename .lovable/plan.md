# แก้ "ไม่พบสถานี BANGKOK METROPOLIS ในไฟล์" (กรมอุตุฯ ตรวจอากาศ 3 ชม.)

## สาเหตุจริง (ตรวจแล้ว)

สถานี **48455 BANGKOK METROPOLIS (กรุงเทพมหานคร)** มีอยู่จริงในไฟล์ และโปรแกรมอ่านชื่อ/รหัสถูกต้อง ปัญหาไม่ได้อยู่ที่ชื่อสถานี แต่อยู่ที่ **ไฟล์ที่กรมอุตุฯ ส่งมาในบางรอบไม่ครบ**:

| ขนาดไฟล์ที่ได้รับ | เกิดขึ้นเมื่อ | ผล |
|---|---|---|
| ~122 KB (126 สถานี) | ปกติ | ดึงสำเร็จ |
| 8.5 KB (มีแค่ไม่กี่สถานี) | 19:12 น. วันนี้ | "ไม่พบสถานี BANGKOK METROPOLIS" |
| 477 ไบต์ (ไม่มีสถานีเลย) | 19:32 น., 10:05 น. | "ไฟล์ว่าง" |

กรมอุตุฯ สร้างไฟล์ใหม่ทุก 3 ชั่วโมง (01, 04, 07, 10, 13, 16, 19, 22 น.) ช่วงไม่นานหลังเวลาเหล่านี้ไฟล์มักกำลังถูกเขียนอยู่ จึงได้ไฟล์ครึ่งเดียวหรือไฟล์ว่าง การลองซ้ำทันที 3 ครั้งภายในไม่กี่วินาทีจึงได้ไฟล์เสียเหมือนเดิม และระบบนับว่า "ตรวจสอบไม่ได้" ทั้งที่ข้อมูลรอบก่อนยังใช้ได้

## แนวทางแก้ (เสนอใช้ทั้ง 4 ข้อร่วมกัน)

1. **ตรวจไฟล์ว่าครบก่อนใช้** — ถ้าสถานีน้อยกว่า ~100 แห่ง หรือไม่มีสถานีเลย ให้ถือว่า "ไฟล์ยังไม่พร้อม" ไม่ใช่ "ไม่พบสถานี"
2. **รอแล้วลองใหม่แบบเว้นระยะ** — ลองใหม่หลัง ~2 นาที และ ~5 นาที (แทนการลองถี่ ๆ ทันที) และหลีกเลี่ยงช่วง 0–20 นาทีหลังเวลาสร้างไฟล์
3. **สถานีสำรองใกล้กรุงเทพฯ** — ถ้าไฟล์มาแต่ไม่มี 48455 ให้ใช้สถานีถัดไปตามระยะ: คลองเตย (48454) → บางนา (48453) → ดอนเมือง (48456) → สุวรรณภูมิ โดยแสดงชัดว่า "ใช้ค่าจากสถานี X แทน" (ค่าไม่ปน ไม่เฉลี่ย)
4. **คงค่ารอบล่าสุดที่ดี** — ถ้าทุกวิธีล้ม ให้สถานะเป็น "ใช้ค่ารอบก่อน (เวลา …)" พร้อมเหตุผล "กรมอุตุฯ ส่งไฟล์ไม่ครบ (n สถานี)" แทน "ตรวจสอบไม่ได้" ตราบที่ค่ายังไม่เก่าเกิน 1 วัน

## ผลที่ผู้ใช้จะเห็น

- หน้าแหล่งข้อมูลแสดงสาเหตุชัด: "ไฟล์ไม่ครบ (มี 12 จาก 126 สถานี) — ลองใหม่ 19:35"
- เมื่อใช้สถานีสำรอง จะมีป้าย "สถานีสำรอง: บางนา"
- หน้าข้อมูลทั้งหมดเพิ่มตารางเล็ก: สถานีใกล้กรุงเทพฯ 5 แห่ง กับค่าล่าสุด
- สคริปต์ Python สำหรับตรวจเอง: ดาวน์โหลดไฟล์, นับสถานี, แสดงสถานีในกรุงเทพฯ/ปริมณฑลพร้อมระยะห่างและค่าฝน/อุณหภูมิ

## รายละเอียดทางเทคนิค

- `src/lib/tmd3h.ts`: `parseTmd3h` คืน `complete` (stations ≥ 100) และ `fallback` เลือกตาม `NEAR_BKK` (เพิ่ม 48429 สุวรรณภูมิ ถ้ามีในไฟล์); เพิ่ม test vitest สำหรับไฟล์ 477B / 8.5KB / เต็ม
- `src/lib/connectors.server.ts` (connector 3 ชม.): ไฟล์ไม่ครบ → throw error แบบ retryable พร้อมจำนวนสถานี; ใช้ queue retry delay สั้น (2/5 นาที) เฉพาะกรณีนี้; ค่าจากสถานีสำรองบันทึกใน observation meta (`station_id`) — metric ids เดิม `rain_bkk`/`tmax_bkk` ไม่เปลี่ยน
- `completeness.ts`: สถานะ "ใช้ค่ารอบก่อน" เมื่อมีค่าที่ไม่เก่าเกิน `stale_after_days`
- สคริปต์ `scripts/tmd3h_bkk.py` (อ่านอย่างเดียว)
- ไม่เปลี่ยน detection/ranking/cutoff/impact/cron; ไม่เผยแพร่เว็บ
