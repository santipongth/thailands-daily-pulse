# แผนยกระดับ Thailand Daily Signals ให้พร้อมใช้งานจริง (production)

ตรวจจากตัวโค้ดจริง (32 หน้า), ฐานข้อมูล, คิวงาน และประวัติการดึงข้อมูล แบ่งงานเป็น 4 ระยะตามความเร่งด่วน อนุมัติทั้งแผนหรือบอกได้ว่าจะเริ่มเฉพาะระยะไหน

## สิ่งที่พบ (สรุป)

| ด้าน | สภาพตอนนี้ | ความเสี่ยง |
|---|---|---|
| ความปลอดภัย | ปุ่มที่เปลี่ยนค่าทั้งเว็บ (วิธีดึง Longdo/ThaiWater, ลิงก์วันหยุด, สั่งดึงใหม่) ใครก็กดได้ มีแค่ตัวจำกัดความถี่ | สูง: คนนอกเปลี่ยนการตั้งค่าของทั้งเว็บได้ |
| ความเสถียร | คิวงานมี 27 งานที่ล้มถาวร ไม่มีใครถูกแจ้งเตือน | กลาง: Brief ขาดข้อมูลแบบเงียบ ๆ |
| ข้อมูล | ตารางเก่า 3 ตาราง (gov_datasets/snapshots/changes) ว่างและไม่ได้ใช้; ไฟล์ดิบเก็บถาวร (~600 ไฟล์ใน 2 สัปดาห์ ส่วนใหญ่ซ้ำแบบไม่เปลี่ยน) | กลาง: พื้นที่โตไม่หยุด |
| การทดสอบ | มีชุดทดสอบแค่ 2 ไฟล์ ส่วนตรวจจับ/จัดอันดับ/ผลกระทบไม่มีทดสอบ | กลาง: แก้แล้วพังโดยไม่รู้ |
| API สาธารณะ | ไม่มีตัวจำกัดความถี่และ cache | กลาง: ถูกยิงหนักจะกินฐานข้อมูล |
| การแจ้งเตือนผู้ใช้ | แจ้งเตือนได้เฉพาะตอนเปิดเว็บค้างไว้ | ฟีเจอร์ขาด |

## ระยะ 1 — ความปลอดภัย (ทำก่อน)
1. เพิ่มการเข้าสู่ระบบสำหรับผู้ดูแลเท่านั้น (ผู้อ่านทั่วไปยังไม่ต้องล็อกอินเหมือนเดิม)
2. ย้ายการตั้งค่าทั้งเว็บ (วิธีดึง, ลิงก์วันหยุด, สั่งดึงใหม่, คิวงาน) ไปหน้า "ผู้ดูแล" ที่ต้องล็อกอิน; หน้าตั้งค่าของผู้อ่านเหลือแค่ค่าบนเครื่องตัวเอง
3. ปิดช่องทางที่เปิดไฟล์ดิบ/ลิงก์ส่วนตัวให้เฉพาะสิ่งที่ตั้งใจเปิด และรันการตรวจความปลอดภัยฐานข้อมูลอีกครั้ง

## ระยะ 2 — ความเสถียรและการเฝ้าระวัง
1. หน้า "สุขภาพระบบ" สำหรับผู้ดูแล: งานที่ล้ม, แหล่งที่ล้มติดกันหลายรอบ, เวลาที่ Brief ออก, ปุ่มสั่งรันงานที่ล้มอีกครั้ง
2. แจ้งเตือนผู้ดูแลทางอีเมลเมื่อ Brief 06:00 ไม่ออก หรือแหล่งข้อมูลล้มเกิน 6 ชั่วโมง
3. ล้างงานล้มเก่าที่ค้างอยู่ และเก็บประวัติคิวไว้ 30 วัน

## ระยะ 3 — ข้อมูลและประสิทธิภาพ
1. ลบตารางเก่าที่ไม่ใช้ 3 ตาราง
2. ไฟล์ดิบ: เก็บถาวรเฉพาะไฟล์ที่เนื้อหาเปลี่ยน ไฟล์ซ้ำเก็บแค่บันทึกว่าดึงเมื่อไร (ไม่ลบหลักฐานที่ถูกอ้างถึงใน Signal/Brief)
3. API สาธารณะ: cache สั้น ๆ + จำกัดจำนวนคำขอต่อนาที
4. ทำให้หน้าเว็บเปิดเร็วขึ้น: ลดข้อมูลที่โหลดซ้ำ, ปรับรูปภาพ AI ให้ขนาดเล็กลง

## ระยะ 4 — ฟีเจอร์ใหม่
1. **แจ้งเตือนแม้ไม่เปิดเว็บ** (ติดตั้งเป็นแอปบนมือถือ/web push): เลือกหมวดที่อยากรับ เช่น น้ำมัน ทอง แผ่นดินไหว
2. **สรุป Brief ทางอีเมลรายวัน** สำหรับผู้ที่สมัครรับ (ใส่แค่อีเมล ยกเลิกได้)
3. **รูปแชร์โซเชียลของ Brief แต่ละวัน** (ภาพปกตอนแชร์ลิงก์ใน LINE/Facebook)
4. **ค้นหา** Signal/เหตุการณ์ย้อนหลัง

## ตรวจรับ
- ชุดทดสอบเพิ่มสำหรับการตรวจจับ, จัดอันดับ, ผลกระทบครัวเรือน, ตัวอ่านไฟล์แต่ละแหล่ง
- ตรวจทุกหน้าบนมือถือและเดสก์ท็อปซ้ำหลังเปลี่ยน
- ยังไม่เผยแพร่จนกว่าจะผ่านทั้งหมด

## รายละเอียดทางเทคนิค
- Auth: Lovable Cloud email + Google, ตาราง `user_roles` + `has_role()`, routes `_authenticated/admin/*`; `setFetchMode`/`setHolidayUrl`/`retrySources`/`refreshData` ใช้ `requireSupabaseAuth` + ตรวจ role admin ก่อนโหลด admin client
- Monitoring: view/fn รวม `ingest_jobs` failed + `source_run_history` streak; cron ตรวจหลัง 06:05 ส่งอีเมลผ่าน Lovable email
- Drop `gov_changes`, `gov_snapshots`, `gov_datasets` (migration); `raw_evidence` เพิ่ม `last_seen_at` + นับซ้ำแทนแถวใหม่สำหรับ sha256 เดิม
- API v1: `Cache-Control: public, max-age=60`, rate limit ตาม IP ในตาราง/app_settings
- Push: service worker + VAPID keys (secret), ตาราง subscriptions (anon insert เฉพาะ endpoint ตัวเอง)
- ไม่เปลี่ยน detection/ranking/cutoff/impact/cron ของ Brief; อัปเดต AGENTS.md ตามโครงสร้างใหม่
