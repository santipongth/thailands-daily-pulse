# พักแหล่งที่ล่มนาน, หน้าตรวจสุขภาพระบบ, แนวโน้มค่าครองชีพ 30 วัน

## 1. พักแหล่งข้อมูลอัตโนมัติเมื่อดึงไม่สำเร็จติดกัน (Circuit Breaker)
- ถ้าแหล่งใดดึงไม่สำเร็จ **3 รอบติดกัน** (นับจากประวัติการดึง) ระบบจะ **พักแหล่งนั้น 4 ชั่วโมง** ไม่ส่งคำขอ (รวม Firecrawl) ในช่วงพัก
- ครบเวลาแล้วส่ง **รอบทดลอง 1 ครั้ง**: สำเร็จ = กลับมาดึงตามปกติ; ไม่สำเร็จ = พักต่อ 6 ชั่วโมง
- ไม่นับเป็นความล้มเหลว: ดึงสำเร็จแต่ไม่มีข้อมูลใหม่, หรือข้อความ "ใช้ค่ารอบก่อน" ของกรมอุตุฯ
- การกด "ดึงตอนนี้" ของผู้ดูแลยังทำงานได้เสมอ (ข้ามการพัก) และสำเร็จแล้วปลดพักทันที
- รอบ 05:00/05:30 ก่อนออกฉบับเช้า: แหล่งที่ถูกพักได้รอบทดลองเสมอ เพื่อไม่ให้ฉบับ 06:00 ขาดข้อมูลเพราะการพักเมื่อคืน
- แสดงสถานะ "พักถึง HH:MM (ล้มเหลว N ครั้งติด)" + ปุ่ม "ปลดพัก" ในหน้าควบคุมแหล่งข้อมูล และในหน้าบันทึกการดึง/หน้า /failures

## 2. Endpoint ตรวจสุขภาพระบบ `/api/public/health`
- ตอบ JSON สาธารณะ อ่านอย่างเดียว ไม่มีข้อมูลลับ (ไม่มี error ดิบ, path ไฟล์, หรือรายละเอียดคิวภายใน)
- เนื้อหา: `status` (ok / degraded / down), DB ตอบได้หรือไม่ + เวลาตอบ, จำนวนงานค้างในคิว + อายุงานที่ค้างนานที่สุด, ฉบับ Brief ล่าสุด (วันที่ + เวลาเผยแพร่ + ล่าช้าหรือไม่), สรุปแหล่งข้อมูล (สด / ค้าง / ถูกพัก) ต่อแหล่ง
- HTTP 200 เมื่อ ok/degraded, 503 เมื่อ down (DB ไม่ตอบ, หรือ Brief วันนี้ยังไม่ออกหลัง 06:30) — ใช้กับ Uptime Monitor ได้ตรง ๆ
- ใช้ rate limit เดียวกับ API สาธารณะ (120 ครั้ง/นาที/IP), ไม่เก็บ cache
- เพิ่มคำอธิบายในหน้า Developers และใน OpenAPI

## 3. หน้าแนวโน้มค่าครองชีพ `/cost-trend`
- ใช้ตะกร้าครัวเรือนเดิม (ปริมาณต่อวันที่ยืนยันแล้ว) × ราคาจริงแต่ละวัน — สูตรเดียวกับกล่องค่าใช้จ่ายครัวเรือน ไม่มีการเดาค่า
- สลับช่วง 7 วัน / 30 วัน
- ด้านบน: ค่าใช้จ่ายต่อวันวันแรก vs วันล่าสุด, **เปลี่ยนสุทธิกี่บาท/วัน และ ≈ บาท/เดือน**
- กราฟ 1: ค่าใช้จ่ายตะกร้ารวมต่อวัน (เส้น)
- กราฟ 2: แยกกลุ่ม น้ำมัน / เนื้อสัตว์และอาหาร / ก๊าซ (เส้นซ้อน) เพื่อดูว่ากลุ่มไหนดันค่าใช้จ่าย
- ตาราง: รายการที่ขึ้น/ลงมากที่สุดในช่วงนั้น (ราคาเริ่ม → ล่าสุด, ผลต่อบาท/วัน)
- วันที่ไม่มีราคาใหม่ใช้ราคาล่าสุดที่รู้ (ระบุชัดในหมายเหตุ); รายการที่ยังไม่มีราคาครบช่วงจะแจ้ง "ข้อมูลไม่ครบช่วง" แทนการเติมค่า
- เพิ่มลิงก์ในเมนูหลัก และลิงก์ "ดูแนวโน้ม 30 วัน →" ใต้กล่องค่าใช้จ่ายครัวเรือน

## รายละเอียดทางเทคนิค
- Migration: เพิ่มคอลัมน์ใน `source_config` หรือตารางใหม่ `source_breaker` (source pk, fail_streak int, open_until timestamptz, probe boolean, updated_at) — anon ไม่ได้อ่าน, admin อ่าน, service role เขียน, พร้อม GRANT
- `drain` (queue.server.ts): หลังจบงาน อัปเดต streak (allFailed → +1, สำเร็จ → 0 และปิด breaker); streak ≥ 3 → open_until = now+4h (รอบทดลองล้ม → +6h)
- `applySourceConfig`/การ enqueue: ตัดแหล่งที่ open_until > now ออก ยกเว้น runKind manual หรือ daily 05:xx (ปล่อยเป็นรอบทดลอง); ใช้กับแหล่งที่ใช้ค่า default ด้วย
- server fn `resetBreaker` ใช้ `requireAdmin`
- `src/routes/api/public/health.ts`: anon client + `hit_rate_limit`, query ด้วย count/head; breaker อ่านผ่าน admin client ภายใน handler แต่ส่งออกเฉพาะ boolean "paused"
- `src/lib/cost-trend.ts` (pure, มี unit test) สร้างอนุกรมรายวันจาก observations ของ BASKET (is_demo=false) แบบ carry-forward; route `/cost-trend` ใช้ recharts + head() ของตัวเอง
- บันทึกกฎใหม่ (breaker, health, cost-trend) ใน AGENTS.md
